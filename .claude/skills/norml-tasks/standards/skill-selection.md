# Suggested skills during planning

Every new or materially amended task and phase plan includes a short, provisional
skill shortlist. Planning helps the next agent find useful procedures; execution
still chooses the actual skills from the current task and available evidence.

## Discover and select

1. Search the user’s installed skill catalog by the desired outcome and artifacts.
   Prefer the existing owning skill. Explicit user/project choices win.
2. Read the matching catalog descriptions and only the contracts needed to resolve
   overlapping ownership or an execution gate. Do not load the whole ecosystem.
3. Cherry-pick the smallest useful set. Identify the likely primary operator,
   supporting specialists and conditional candidates. No fixed count or skill quota.
4. For each candidate, record its exact registered name, why it fits this task and
   when it would help. Link its canonical SKILL.md through the registered skill path
   or a repository-relative link; never save a teammate's absolute checkout path.
5. State that the list is provisional. Missing/unregistered candidates are labelled
   unresolved, never claimed as installed. If no skill fits, record that finding.

## Persist without duplication

Use `## Suggested skills` in the task record. A phase plan may reference those task
sections and add only skills needed for cross-task integration or validation. Keep
the list next to the executable scope, not only in a chat response or raw capture.
Do not create tasks solely to invoke skills and do not duplicate the skill's full
procedure, credential setup or output schema in the plan.

During execution, read the selected skills' current contracts and record the actual
ones used in Evidence or the phase summary. Update candidates when scope/evidence
changes. An unused suggestion is not incomplete work. A mandatory requirement in
an applicable skill remains mandatory; the shortlist cannot waive its gates.

## Boundaries

- Suggesting a skill does not run, install, subscribe to or authenticate a tool.
- A candidate does not grant permission to publish, send messages, spend or deploy.
- Do not turn the list into a rigid chain or invoke every match for completeness.
- Legacy tasks remain readable. Add the section when a task is materially amended;
  do not bulk-rewrite historical records or fail the existing structural helper
  solely because an older task lacks this section.

## Example

An existing-site content task might suggest an installed post-writing skill for the post,
an installed slide-design skill for the slides and a title-writing skill for title options. An image
production skill is conditional on whether the supplied assets are insufficient.
The execution summary records the skills actually used, not every candidate.
