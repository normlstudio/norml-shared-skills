# Organize thoughts and choose the next outcome

## Classify before making tasks

Preserve the user's intent. Distinguish outcomes (goals), binding choices
(decisions), constraints, unanswered questions, speculative ideas, and concrete
actions. Do not turn every sentence into a task or every idea into a commitment.
A question becomes a bounded investigation/decision task when answering it
unblocks an outcome. Keep non-actionable ideas in the capture disposition or
Someday, without inventing a goal the user never expressed.

## Rank with reasons

Apply this order using evidence and the user's explicit priority:

1. Active critical breakages and safety blockers within authorized scope.
2. Work necessary for the user's selected short-term goal or source deadline.
3. Prerequisites that unblock that work.
4. Ready work that most directly advances an active goal.
5. Valuable optional work, then speculative work.

Do not assign made-up impact/effort/ROI scores or forecast completion dates.
Show qualitative evidence: “first because task 004 depends on it,” not “fastest
win.” An explicit requested order wins unless it violates a real dependency;
explain that conflict rather than silently re-ranking it.

Keep Now deliberately small: one selected task per active worker/workstream
by default. A large backlog is not a mandate to start everything. The next
recommendation is one unblocked task plus a reason and the following dependency.
If none is ready, name the concrete unblock action. When a blocker interrupts
Now, preserve the interrupted task and its resume point before selecting another.

## Review triggers

After new input, changed goals, completion, a blocker, or a user-requested
review: recompute ordering, record material reason changes in the task and
short-term goal, regenerate the index, and re-check dependencies. Keep the
long-term goal stable unless the user changes the desired outcome.
