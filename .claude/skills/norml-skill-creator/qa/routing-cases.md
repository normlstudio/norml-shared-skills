# Creator routing cases

These are dry acceptance cases, not permission to create repos or invoke services.

| Input | Expected result |
|---|---|
| General SEO method | Shared collection; portable inputs and data boundary |
| Organization recruiting with private records | Internal private source; records excluded from package |
| One client’s image process | Client owner/prefix; actual asset and access facts verified |
| Client installment flow with undefined variants | Document known path; undefined behavior blocked |
| Existing product-local skill | Product repo; preserve identity/discovery |
| Colleague sharing | Concrete local package or authorized private access; no inferred public host |
| Explicit public package | Classify/distil; preserve internal source and separate edition |
| Third-party collection | Preserve provenance; no implicit global installation |
| Empty placeholder | Clearly incomplete scaffold or pending task |
| Existing target directory | Inspect collision; no replacing unrelated real directory |
| Move procedures plus live reports | Source package separate from data home; hashes preserved |
| Rename a skill support folder | Project data paths remain unchanged |
| Existing default branch named develop | Verify/use actual configured branch |
| Syntax succeeds; checkout flow untested | Static PASS only; behavioral test pending |
| Runtime install repeated | Idempotent result; correct source/adapters unchanged |
| Package-only work | No website/remote release claims or extra publication effects |
