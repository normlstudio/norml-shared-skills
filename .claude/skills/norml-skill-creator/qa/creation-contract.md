# Creation acceptance contract

Record PASS, FAIL, BLOCKED or NOT APPLICABLE with actual evidence for each gate.

- Intent, audience, selected recipe, source precedence and owner are recorded.
- Destination/repository/visibility/data boundaries match requested scope.
- Names agree; target/runtime collisions have been inspected, not overwritten.
- Triggers and disambiguation are grounded; no duplicate vague ownership.
- Real procedures, required prerequisites, failures/hard stops and onboarding exist.
- All local source links resolve; no orphan operational procedure hides from the router.
- Semantic folders describe actual contents; no empty/generic drawers.
- No secrets, copied auth, current client/account datasets or machine-specific paths.
- Relevant syntax and behavioral checks have distinct actual outcomes.
- Human docs match capabilities/version; requested visual surfaces pass desktop/mobile QA.
- Source/move hashes and preservation mapping verify recovery; originals were not prematurely removed.
- Intended runtime discovery was tested, or clearly reported created/not installed.
- Commit/push/install/publication scope obeys user authority; actual branch/remote result is verified.
- Unresolved work is explicit and has a real owner; no invented estimates/deadlines.

Static checks alone do not prove live CMS/payment/publishing behavior. A scaffold, local package,
verified install and public release are separate outcomes. This creator requires no private linter,
registry or renderer. Use available deterministic checks and inspect the actual files. Evaluate
[routing cases](routing-cases.md) when changing creator behavior.
