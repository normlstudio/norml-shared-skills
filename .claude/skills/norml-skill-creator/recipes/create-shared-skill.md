# Create a reusable shared skill

1. Read available installed/collection skills by outcome and changed artifact; inspect overlap.
2. Reuse an existing discipline collection or the user’s explicitly requested source destination.
3. Select a stable unique capability name; preserve established family conventions when useful.
4. Build the generic method at `.claude/skills/{slug}/` through
   [create and verify](../processes/create-and-verify.md).
5. Keep client IDs, environment/account facts and current data outside the method. First run
   resolves the user’s actual project and permissions instead of relying on a company map.
6. Document inputs, actual effects, failure paths and tests. Install/share only at the requested
   scope; verify runtime discovery separately from package correctness.

Shared within a team does not automatically mean public. Access and publication are explicit.
A source collection needs no company-wide registry or role subscription system.
