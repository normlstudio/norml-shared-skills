# Migrate or rename without losing source

## Inventory before copying

Read original source/support, including hidden files and existing archives. Distinguish aliases
from maintained duplicates. Record every path, SHA-256, intended destination and classification:
procedure/static support, context/data, runtime output, secret/auth, placeholder or deprecated source.
Verify ownership/metadata. Keep original recovery outside shared distribution with restricted access.
Empty placeholders become pending work, never invented usable skills.

## Normalize and test

Copy before removing. Preserve useful support/history; isolate current data/reports at their owner.
Rewrite installed-code root, project-data root and external service identity separately; no blanket
replace across those categories. Changing a skill folder does not rename the project’s data folder.
Repair frontmatter/names/links/commands and semantic drawers. Check quoted tilde examples and cwd
assumptions. Scan secret/auth state without printing values. Validate syntax and actual behavior
separately; inspect dry-run mutation guards, failed fetches, skipped/manual checks and cleanup state.
Do not perform live transactions merely to satisfy migration acceptance.

## Cut over only after verification

Verify intended destination/source tree and runtime discovery in a separate test location before
removing originals. Publication checks apply only when publication is requested. Record incomplete
access/install evidence honestly; nondestructive copying may finish while cutover remains blocked.

Recheck source hashes immediately before any move. Changed originals require reconciliation,
never archiving a newer source against an old inventory. Move/remove only exact authorized targets;
verify archived hashes and preserved data. Repair active pointers while retaining historical evidence.
Remove old runtime adapters only when their exact target and replacement discovery are verified.

Report moved/copied source, retained data, recovery path, source mapping, visibility/discovery,
verification limits and blockers. Roll back a failed cutover without discarding concurrent work.
