# Create an organization-private skill

Identify the actual operating owner from its context: administration, sales, team process or
infrastructure. Reuse its authorized private repository/source collection, established names and
data boundaries. The source’s operating method belongs in the package; contracts, account records,
people data, transcripts and current evidence remain in their authorized data home.

Run [create and verify](../processes/create-and-verify.md). Internal dependencies may be explicit
within this private scope; do not pretend the skill is a generic public product. Installation
visibility is not access authorization. Founder/team role schemes are optional user policy,
never a substitute for provider access controls. If only one person owns sensitive material,
resolve its private home instead of placing it in a wider team collection.

Public distribution later requires a separately sanitized edition. No visibility flip or
cross-client access is implied by this route.
