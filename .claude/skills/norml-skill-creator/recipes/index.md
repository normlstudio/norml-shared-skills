# Select creation scope

Use audience/process ownership, not cwd or a source artifact’s location.

- Reusable general method: [shared](create-shared-skill.md).
- Organization-private operation: [internal](create-internal-skill.md).
- Client-specific schema/flow: [client](create-client-skill.md).
- Coupled product implementation: [product](create-product-skill.md).
- Explicit external distribution: [public](prepare-public-skill.md).
- Any source move/rename: additionally [migration](migrate-existing-skill.md).

“Share” may mean named colleague access or public distribution. Proceed with a local sanitized
package when requested; do not infer a public remote or change existing visibility. If audience
changes what material may leave its boundary, resolve that material choice before copying it.
Existing adjacent skills should be extended rather than duplicated. Third-party packs retain
upstream identity/provenance and are not globally installed without authorization. Personal-only
source stays in its configured private home, not an inferred team repository.
