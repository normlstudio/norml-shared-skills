# Prepare a portable sharing edition

A package-only request is concrete work: produce the sanitized package and local distribution
without inferring public hosting, website publication or registration in the recipient’s runtime.

1. Identify canonical source/version, intended audience and permitted public promise.
2. Read every support file; classify each as include/rewrite/omit before copying.
3. Include portable procedures/templates/helpers; rewrite company paths, credential conventions,
   account assumptions and private-skill dependencies; omit live data, auth state and private history.
4. Preserve source originals. Public edition gets its own stable identity/version/changelog.
5. Normalize semantic folders and relative links. First-run inputs resolve the user’s actual roots,
   provider identities, credentials and authority through supported mechanisms.
6. Generate truthful human docs and run syntax/behavior/privacy/link/layout checks as applicable.
7. Generate any requested ZIP from the exact reviewed package tree, inspect its contents and hash.
8. Report package versus install/publication verification independently. Only execute additional
   hosting/release/install surfaces when explicitly requested.

Never change a private repo’s visibility to make a skill public. No client material, private
sibling dependency, copied auth session or machine-specific path may cross the package boundary.
A free-standing edition remains usable without an organization ecosystem installer.
