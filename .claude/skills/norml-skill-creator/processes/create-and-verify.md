# Create and verify a grounded skill

## 1. Inspect

Read canonical source, project instructions, repository status and adjacent capabilities.
Record audience, selected recipe, build/scaffold/extend/migrate intent, name, destination,
data/context home and authority. Check target and installed names; updates reuse the same owner.
Never overwrite an existing real directory or unrelated link. Resolve substantive overlap first.

## 2. Resolve source ownership

Reuse the verified repository or user-configured source folder. Clone/create remotes only under
explicit authority and supported authentication. Preserve existing branch and visibility policy.
Do not silently create a substitute owner when access fails. Private-by-default proposals still
need an authorized concrete remote creation action.

## 3. Author source first

- Scaffold: provide requested shape and clearly identify missing procedures/testing.
- Build: write complete source-grounded operational steps, inputs, outputs, failures and verification.
- Extend: preserve current behavior/manual edits; add requested scope and update affected links.
- Migrate: preserve source before normalization and follow the separate migration gates.

New edition 1.0.0; updates semantic bump plus concise changelog entry. Source precedence applies
to individual facts. Real process/state transitions and permitted side effects matter more than
polished prose. Unknown variants stay blocked. Scripts must fail closed and avoid secret output.

## 4. Document

Write a human Markdown guide from the complete source: pitch, real triggers, inputs/effects,
representative source architecture, normal workflow, limits and failure recovery. No guessed
claims. Optional renderer output must be generated deterministically, visually checked at desktop
and mobile, and tied to the same version. Update collection index for actual package changes.

## 5. Verify and optionally install

Check naming, semantic folders, all relative links, secret/private boundary and relevant script
syntax/behavior. Run the [creation contract](../qa/creation-contract.md). Verify only authorized
side effects; syntax success is not proof of a payment, CMS or publishing integration.

Install only to requested runtime scope using its supported mechanism. Resolve names/targets
before writing; preserve existing installation collisions. Validate discovery in a clean temporary
runtime if possible, then repeat install to prove idempotency. A project-local skill does not
become globally registered by inference. Report created/not installed when appropriate.

## 6. Publish only as authorized

Review exact changed paths and user commit/push permissions; preserve unrelated WIP and hooks.
Verify actual default/integration branch and remote result. Public package, source publication,
ZIP distribution and website release are distinct surfaces. Report achieved surfaces and blockers;
never declare unexecuted install or live behavior verified. Keep remaining work at its actual owner.
