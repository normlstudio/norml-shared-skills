# Resources, guides and downloads

Family ID: `resources`. This overview describes the entire set of related pages.
Member files are flat siblings; actual project pages are instances of these specs.

## Purpose and fit

Visitors need maintained educational/support material beyond a chronological blog.

**Skip or use another family:** Do not duplicate a blog article as a resource merely to fill another archive.

## Canonical entity and model

One resource with an explicit format (guide, download, documentation article, video or another approved kind).

Collection with format/topic classification; deep documentation can use a true parent-child hierarchy.
This is candidate modeling guidance; `WordPress architecture review` owns the actual
WordPress primitive. Match an inherited model before proposing another one.

## Relationships, depth and combinations

Resources hub → format/topic archive → resource single; optional guide chapter pages.
Read [architecture principles](../../standards/architecture.md) before selecting
depth, classifications or combinations. Parent URLs do not dictate CMS storage.
Intersections reference canonical entities and have one owner and canonical route.
