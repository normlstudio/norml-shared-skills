# Norml Page Types

> Choose coherent page families, canonical routes and eligible intersections before making a
sitemap.

## The problem

A list of URLs can hide unclear entity ownership or produce hundreds of near-duplicate pages.

Family/member contracts distinguish hubs, singles, categories, utilities and real relationship
pages.

## How to use it

| When you want to… | Say something like… |
|---|---|
| What page types should this site have? | “What page types should this site have?” |
| Suggest website architecture | “Suggest website architecture” |
| Plan industry and service intersections | “Plan industry and service intersections” |
| Add a page type | “Add a page type” |

## A typical run

1. Match a services-and-areas brief against index.md and the services/areas-of-service contracts.
2. Record hub/single availability separately from actual WordPress query roles.
3. Evaluate each proposed service-area pair for truthful availability and unique maintained content.
4. Choose include, embed, defer or omit and pass the recorded contract to sitemap planning.

## Details

### Inputs

- Project brief, existing inventory, real entity facts and architecture decisions; none needed for
catalog-only questions.

### What it creates or changes

- Family/member recommendation and architecture record with disposition, canonical identity/route,
parent relationships and unresolved dependencies.

### Capabilities

- **Family catalog:** 33 families with linked member specifications and fit/skip rules.
- **Canonical relationships:** Separate navigation, route, entity and CMS hierarchy.
- **Intersection gates:** Evidence and maintainable unique content before page multiplication.
- **Extension templates:** Family/member templates with index and acceptance rules.

### Limits

- No CMS writes, live routes, implementation or deployment.
- Does not prescribe visual tokens or block order.
- Proposed, approved-planned and observed pages remain distinct.

### When something is missing

Read the runtime contract and relevant bundled procedure. Report missing source
facts, access, required content or verification as unresolved/blocked; continue
independent checks. Keep project decisions and credentials outside the package.
Never guess evidence or treat a template/default as a verified live result.

### Installation and source

Copy this complete folder into the supported skill directory of your chosen
agent runtime. The runtime must discover SKILL.md and its relative supporting
files. See the collection guide for tested local installation. No remote CLI
installation or runtime compatibility is promised without that verification.

Source: the supplied norml-shared-skills collection. This package is standalone;
related Norml packages mentioned in SKILL.md are optional companions.
